# 新手学习指导

本文档面向第一次接触该项目的新成员，说明运行 `build_define_v2.ipynb` 之前需要做的全部准备工作。

---

## 一、这个文件是做什么的？

`build_define_v2.ipynb` 是一个 **Jupyter Notebook**，它的最终目标是把研究项目的 SDTM 规格书、标准码表、XPT 数据文件等来源，自动组装生成符合 CDISC Define-XML 2.1 规范的 `define.xml` 文件。

整体流水线如下：

```
[部门标准 xlsx]  [项目规格 xlsx]  [SDTM XPT 数据]  [注释 aCRF PDF]
        │                │               │                │
        ▼                ▼               ▼                ▼
   [中间 YAML 产物（dept_std/ + study_std/ + datasets/）]
        │
        ▼
   define.xml  ──→  在浏览器中用 define2-1.xsl 查看
```

每个代码 Cell 负责一个环节，**必须按顺序从头到尾运行**（Run All）。

## 二、需要安装的软件

### 2.1 Python（必须）

- **版本要求**：Python 3.9 或以上（推荐 3.10 / 3.11）
- **下载地址**：https://www.python.org/downloads/
- 安装时勾选 **"Add Python to PATH"**

验证安装是否成功（在 Windows 命令提示符 / PowerShell 中运行）：
```powershell
python --version
pip --version
```

---

### 2.2 VS Code（推荐编辑器）

- **下载地址**：https://code.visualstudio.com/
- 安装完成后，在 VS Code 的扩展市场（Extensions，快捷键 `Ctrl+Shift+X`）中搜索并安装以下两个插件：

| 插件名 | 说明 |
|---|---|
| **Python**（微软官方） | Python 语言支持，提供代码提示和调试 |
| **Jupyter**（微软官方） | 让 VS Code 能打开和运行 `.ipynb` 文件 |

安装后重启 VS Code。

---

### 2.3 必要的 Python 包

在命令提示符或 VS Code 的终端（`Ctrl+\``）中执行以下命令，一次性安装所有依赖：

```powershell
pip install pyyaml openpyxl pymupdf pyreadstat pandas
```

各包用途说明：

| 包名 | 用途 |
|---|---|
| `pyyaml` | 读写 YAML 中间文件 |
| `openpyxl` | 读取 Excel (.xlsx) 规格书和标准库文件 |
| `pymupdf`（导入名 `fitz`） | 解析注释版 aCRF PDF，提取变量-页码映射 |
| `pyreadstat` | 读取 SAS XPT 格式的 SDTM 数据文件 |
| `pandas` | 配合 pyreadstat 处理 XPT 数据 |

> **注意**：`yaml`、`os`、`re`、`pathlib`、`xml`、`collections` 等均为 Python 内置标准库，无需单独安装。

## 三、需要准备的输入文件

在运行 notebook 之前，以下文件必须**提前存在**。文件路径以 `config.yaml` 中的配置为基准。

### 3.1 项目配置文件（工作目录下）

| 文件 | 说明 |
|---|---|
| `config.yaml` | 项目总配置，指定各目录路径、输入文件名、输出语言等 |

> 打开 `config.yaml`，确认以下关键配置与本机实际路径和文件名一致：
> - `sdtm_dir`：SDTM XPT 文件所在目录（相对于工作目录）
> - `dept_dir`：部门标准库目录（默认 `dept_std`）
> - `study_dir`：项目层产物目录（默认 `study_std`）
> - `dept_files`：部门标准 xlsx 文件名（共 4 个）
> - `study_files`：项目规格 xlsx 文件名（共 3 个）

---

### 3.2 部门标准库文件（放在 `dept_std/` 目录下）

这些是**部门统一维护**的标准文件，需向团队负责人获取：

| 文件 | 说明 |
|---|---|
| `SDTM_CT_2024-09-27.xlsx` | CDISC 官方 SDTM 控制术语包（CT） |
| `computation-methods-studyname_sdtm_v1.1.xlsx` | 部门级派生方法库 |
| `valuelevel-studyname_sdtm_v1.1.xlsx` | 部门级值水平元数据（VLM + WhereClause） |
| `comments-studyname_sdtm_v1.1.xlsx` | 部门级注释库 |

> 文件名须与 `config.yaml` 中 `dept_files` 下的配置完全一致。

---

### 3.3 项目专属文件（放在 `study_std/` 目录下）

这些是**针对本研究**的文件，由项目数据管理团队提供。文件名随研究号变化，须与 `config.yaml` 中 `study_files` 的配置完全一致（下表以当前配置的研究号 `SHR-1234-III-301` 为例）：

| 文件 | 说明 |
|---|---|
| `spec-sdtm-SHR-1234-III-301-define.xlsx` | 项目 SDTM 规格书（包含各域变量定义、溯源、方法等） |
| `standard-codelist-SHR-1234-III-301_for_define.xlsx` | 项目层标准码表库（含研究标记列 X） |

> 换研究时，这两个文件名以及 `config.yaml` 中的 `study_id`、`study_files` 都要同步更新。
> `study_std/` 目录既存放上面两个输入 xlsx，也存放 notebook 运行后生成的 yaml 中间产物（`study.yaml`、`codelists.yaml`、`methods.yaml`、`comments.yaml` 等）。

---

### 3.4 SDTM XPT 数据文件（放在 `config.yaml` 中 `sdtm_dir` 指定的目录下）

| 文件 | 说明 |
|---|---|
| `ae.xpt`、`dm.xpt`、`lb.xpt` … 等所有域（含 `supp*.xpt`） | SAS Transport 格式的 SDTM 数据文件 |
| `acrf.pdf` | 注释版 aCRF（用于提取变量与 CRF 页码的对应关系；对应 `config.yaml` 中 `study_files.acrf_pdf`） |
| `complexalgorithms.pdf` | 复杂算法补充文档（`study.yaml` 会引用） |

> `study.yaml` 中引用了 `acrf.pdf`、`complexalgorithms.pdf` 等文档。如果某个 PDF 暂缺，生成的 define 中对应链接会指向一个不存在的文件，请提前向项目团队索取或在 `build_study_yaml` cell 中移除对应引用。

> **关于示例数据**：本仓库出于脱敏考虑，`sdtm_dir` 下只上传了几个重点域的 XPT 作为演示样例，并非全部域。你完全可以把这些样例替换成自己项目的 XPT 数据来跑通整个流程——只需保证文件名与 `datasets/toc.yaml`、`config.yaml` 的配置对应即可。缺少的域要么用你自己项目的对应 XPT 补齐，要么从 `toc.yaml` 中移除，避免运行时出现"缺域"提示。

---

### 3.5 参考资料（`define_src/`）

`define_src/` 目录当前只包含 `README.md`（设计说明），运行 notebook 不需要在此目录额外准备文件。`codelists.yaml`、`methods.yaml`、`comments.yaml` 这些项目层聚合产物是由 notebook 自动生成并写入 `study_std/` 目录的，无需手动准备。

> 如果想了解整体设计思路，可先阅读 `define_src/README.md`。

## 四、修改工作目录路径

打开 `build_define_v2.ipynb`，找到**第一个代码 Cell**（注释标题"读取项目配置 config.yaml"下方），将 `WORK_DIR` 改成你本机的实际路径：

```python
# 修改这里 ↓ 改成你本机的实际路径
WORK_DIR = Path(r"C:\你的路径\ai-define-master\ai-define-master")
```

> 路径前加 `r` 前缀是为了避免反斜杠被转义。路径中如有中文字符，确保系统支持 UTF-8。
> 该 cell 会 `chdir` 到 `WORK_DIR`，后续所有相对路径都基于此目录；若 notebook 里还有另一个单独定义 `WORK_DIR` 的 cell，以这个 config cell 为准。

---

## 五、填写研究元数据占位符

在 notebook 中找到 `build_study_yaml` cell（注释里写着"生成 study_std/study.yaml"），在"需要手动填写的字段"区块逐一核对。凡是形如 `{{FIELD_NAME}}` 的值都必须替换成实际内容：

```python
STUDY_DESCRIPTION  = "三期肿瘤对照试验"       # 研究中文全称，按本研究实际修改
ORIGINATOR         = "{{ORIGINATOR}}"         # → 改为 申办方公司全称
MEDDRA_VERSION     = "{{MEDDRA_VERSION}}"     # → 改为 所用 MedDRA 版本，如 "28.0"
WHODRUG_VERSION    = "{{WHODRUG_VERSION}}"    # → 改为 WHO Drug 版本，如 "GLOBALB3Mar23"
```

同一 cell 内还有一组版本号字段，通常沿用默认值即可，换标准版本时才需调整：

```python
SDTMIG_VERSION     = "3.3"       # SDTM-IG 版本
SDTM_VERSION       = "1.7"       # SDTM 版本
DEFINE_VERSION     = "2.1.0"     # Define-XML 版本
ODM_VERSION        = "1.3.2"     # ODM 版本
```

> 当前 notebook 里 `STUDY_DESCRIPTION` 已填为示例值 `"三期肿瘤对照试验"`，`ORIGINATOR`、`MEDDRA_VERSION`、`WHODRUG_VERSION` 仍是 `{{...}}` 占位符，运行前必须替换。运行后 Cell 末尾会列出仍需手动核对的字段，根据提示逐一填完。

## 六、运行步骤

准备工作完成后，按以下步骤运行：

1. 用 VS Code 打开工作目录文件夹（`文件` → `打开文件夹`）
2. 打开 `build_define_v2.ipynb`
3. 在右上角选择 Python 解释器（点击 **"Select Kernel"** → 选择安装了依赖包的 Python 环境）
4. 点击顶部菜单 **"Run All"**（或依次按 `Shift+Enter` 逐 Cell 运行）
5. 观察每个 Cell 末尾的打印报告，确认无 ❌ 错误；如有 ⚠ 警告，根据提示处理
6. 所有 Cell 运行完毕后，在工作目录下找到生成的 **`define.xml`**

## 七、查看生成结果

notebook 的最终产物是工作目录下的 `define.xml`。查看渲染效果时，将 `define.xml` 和 `define2-1.xsl` 放在同一目录（本项目默认已在工作目录），用 **本地 Web 服务器**（而非直接双击）打开即可（部分浏览器因安全策略限制本地 XSL 加载）：

## 八、常见问题排查

| 现象 | 可能原因 | 解决方法 |
|---|---|---|
| `ModuleNotFoundError: No module named 'fitz'` | pymupdf 未安装 | `pip install pymupdf` |
| `ModuleNotFoundError: No module named 'pyreadstat'` | pyreadstat 未安装 | `pip install pyreadstat` |
| `AssertionError: WORK_DIR 不存在` | WORK_DIR 路径配置错误 | 修改第一个 Cell 中的 `WORK_DIR` |
| `FileNotFoundError: xxx.xlsx` | 输入文件缺失或文件名与 config.yaml 不匹配 | 检查文件是否存在，核对 `config.yaml` 中的文件名 |
| Cell 运行后打印 `⚠ 断链引用 N 处 ❌` | YAML 中有 OID 引用但对应定义不存在 | 检查 datasets/ 下对应域文件中的 method/codelist/comment 引用 |
| `⚠ 缺域` 提示 | toc.yaml 中列了某域，但 datasets/ 下没有对应 yaml 文件 | 运行 build_domain Cell 生成该域文件，或从 toc 中移除该域 |
| XPT 读取失败 | XPT 文件路径或编码问题 | 确认 `config.yaml` 中 `sdtm_dir` 指向实际 xpt 文件所在目录 |
